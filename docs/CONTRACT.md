# Navelo contract v1

Three modules: shared (wire models, range/parser primitives, NSD and encrypted credential utility), server-app (SAF, phone-owned metadata, HTTP and phone UI), tv-app (cached library/metadata, playback and couch UI). Packages are `app.navelo.shared`, `app.navelo.server`, and `app.navelo.tv`. Compile/target 36, min 26, Kotlin 2.1.20, Java 17. Both applications are version 1.0.3.

JSON is kotlinx serialization Protocol.json. Enum values UPPER_CASE. IDs opaque SHA-256 of root+document ID, never file content. Server stores content URIs privately. Revisions monotonically increase on actual changes. Original bytes only, no transcoding.

## HTTP
GET /api/v1/server public ServerInfo. All library/media endpoints require Authorization: Bearer TOKEN. GET /api/v1/library -> LibraryResponse. GET /api/v1/items?offset=0&limit=500[&revision=...] -> ItemsResponse, stable snapshot pagination; unchanged only if requested revision equals current. Optional rootId/parentId filters. TV full snapshot replacement only when all pages with same revision arrive. POST /api/v1/rescan is authorized, queues a background scan, and returns `202 Accepted` with the current LibraryResponse. Existing snapshot lookup and playback do not wait for the storage walk.

With `rescan-status-v1`, the rescan response includes a reserved `scanGeneration`. Concurrent requests share the pending generation. Public ServerInfo exposes `libraryRevision`, `scanGeneration`, `completedScanGeneration`, and nullable `scanError`; completion is independent of whether files changed. Generations reset on phone process restart. The TV waits for completion before reporting success, handles errors/restarts/timeouts, and uses request-only wording for older phones without this capability.
GET|HEAD /media/{opaqueId}: original bytes, single byte range, 206/416 headers, bounded buffer, true descriptor seek. Unknown IDs 404; inaccessible providers 503; nonseekable providers must fail range explicitly instead of skipping gigabytes. OPTIONS has Allow; never public media. Subtitle items use same authenticated endpoint.
POST /api/v1/playback -> PlaybackReport, best effort actual playback reporting.
GET /api/v1/thumbnail/{opaqueId}: same bearer authentication, JPEG frame up to 640×360. Server advertises `thumbnails`. Returns ETag and `Cache-Control: private, max-age=86400`; matching If-None-Match returns 304. Unknown/non-video/no frame returns 404; busy or failed extraction returns 503 with Retry-After. One extractor plus one waiter (at most two seconds) prevents artwork from occupying all streaming workers. Phone cache is capped at 48 MiB and keyed by ID, file size and modification time. TV image cache additionally includes server identity and preserves entries across IP changes.
ServerInfo advertises `phone-metadata-v1` when the following phone-owned metadata API is available. Every endpoint uses the same paired bearer authentication as the library:

- `GET /api/v1/metadata` returns the current cached `MetadataSnapshot` immediately. It may schedule bounded matching in the background but never waits for TMDB. Its revision is independent from the media-library revision.
- `GET /api/v1/metadata/search?itemId=ITEM&q=QUERY` returns `MetadataSearchResponse` for an existing library item and owner-entered query.
- `POST /api/v1/metadata/match` accepts `MetadataMatchRequest` and saves the selected match after validating the item and provider identity.
- `POST /api/v1/metadata/clear` clears phone-owned provider metadata and provider-artwork caches. It does not remove media, folder grants, pairing, watch state or video-frame thumbnails.
- `GET /api/v1/artwork/{opaqueId}` serves phone-cached provider artwork. The opaque ID is generated by the phone; clients never supply or receive a provider URL as a fetch target.

Provider errors and timeouts affect metadata responses/work only. They do not change server identity, library revision, pairing, media availability or playback status.
POST /api/v1/pair body PairRequest (clientSecret is random 32-byte URL-safe base64). Returns PairTicket pending. POST/poll frequency limited. GET /api/v1/pair/{requestId} requires X-Pair-Secret matching request. Pending requests expire in 5 minutes. Phone Allow approves, Deny rejects. Approved poll returns token (256-bit random). PIN displayed both sides for verification; do not permit knowledge of six-digit PIN alone to approve. Store token encrypted using Android Keystore; server stores SHA-256 token hash. Revocation on phone supported. Persist serverId and clientId across ordinary restarts. Trust keyed on serverId not address. Cleartext HTTP on trusted home LAN; credentials encrypted at rest, LAN traffic not encrypted (document).

## Metadata wire models
`MediaMetadata(id:Long,title:String,overview:String="",posterUrl:String?=null,backdropUrl:String?=null,year:String="",runtimeMinutes:Int=0,genres:List<String>=emptyList(),cast:List<String>=emptyList(),rating:Double=0.0,seasonPosterUrl:String?=null,episodeTitle:String?=null,episodeOverview:String?=null,episodeImageUrl:String?=null,episodeAirDate:String?=null,mediaType:String="")`. Every non-null artwork field is a relative authenticated `/api/v1/artwork/{opaqueId}` URL.

`MetadataSnapshot(revision:Long,configured:Boolean,items:Map<String,MediaMetadata>)`, where map keys are Navelo media item IDs. `configured` reports whether the phone build has an effective provider credential; it does not claim that the credential or current network has been validated.

`MetadataSearchResponse(results:List<MediaMetadata>)`.

`MetadataMatchRequest(itemId:String,tmdbId:Long,mediaType:String)`.

## Discovery
NSD _navelo._tcp. TXT id=<server UUID>, api=1, name=Media Phone. Shared NaveloDiscovery(context): servers: StateFlow<List<DiscoveredServer>>, start(), stop(); DiscoveredServer(serverId:String, displayName:String, host:String, port:Int) with baseUrl:String. resolve serialized for older Android. Network changes re-register/re-discover. Shared NaveloAdvertiser(context): start(serverId,displayName,port), stop().

## Phone backend facade (server agent owns)
ServerRuntime.get(context) singleton, state: StateFlow<ServerState>. ServerState(running:Boolean=false, scanning:Boolean=false, roots:List<MediaRoot>=emptyList(), pending:List<PendingPair>=emptyList(), devices:List<TrustedDevice>=emptyList(), message:String?=null, streamingTitle:String?=null, port:Int=8765, serverId:String=""). suspend addRoot(uri:Uri,type:RootType), removeRoot(id:String), rescan(), approve(requestId:String), deny(requestId:String), revoke(clientId:String). start()/stop() start/stop MediaServerService. Phone MainActivity owned by lead. Agent owns manifest service entries; lead owns app icon/theme/activity wiring.

## TV core facade (TV core agent owns)
TvRepository consumes the phone metadata API and exposes the last complete metadata map through `TvState`. Owner Fix Match and clear actions call the paired phone; the repository contains no TMDB token storage, BuildConfig token, direct provider request or provider URL. Metadata polling is independent from library refresh and must not set `online=false`, clear cached media, or interrupt playback when it fails.
TvState includes `items:List<MediaItem>`, `metadata:Map<String,MediaMetadata>`, watch/discovery/pairing/connection state, `settings:TvSettings`, and `serverName:String`. Defaults are empty/false. Cached metadata survives TV restarts and phone/provider unavailability.
WatchProgress(positionMs:Long=0,durationMs:Long=0,lastPlayed:Long=0,watched:Boolean=false).
TvSettings(autoNext:Boolean=true,subtitles:Boolean=true,tmdbConfigured:Boolean=false), where `tmdbConfigured` mirrors the latest phone snapshot and is not a user toggle or locally stored credential.
@Composable NaveloPlayer(item:MediaItem,repository:TvRepository,startOver:Boolean,onBack:()->Unit,onNext:(MediaItem)->Unit) owned core agent. Takes next episode from repository. Media3 PlayerView with remote controls, language/subtitles, progress every 5s and on pause/back, lifecycle release. TV UI agent owns MainActivity and all other screens, reads repository state. Add API fields only collaboratively.

## Shared ownership
Lead owns root Gradle and shared implementations. Agents may add test files to their owned modules. Do not edit another agent's files. Communicate contract changes. No pseudo-code placeholders; document platform/device verification limits honestly.

## Hotspot addition
Shared discovery also sends `NAVELO_DISCOVER_V1` UDP datagrams to port 8766 using directed interface broadcasts, limited broadcast and default gateways. Phone listens on wildcard UDP and replies to the sender with JSON `{navelo:1,id,name,port}`. Client uses the reply source address, never a remotely supplied URL. The same public identity must be validated through `/api/v1/server` before authenticated access. This fallback has no internet/validated-network dependency. There is no hotspot toggling permission or tethering configuration: the owner enables the phone hotspot in Android settings and joins the TV normally. Discovery is automatic in either topology.
